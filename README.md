# nixos

Personal NixOS + Home Manager configuration, built as a flake. Manages one
NixOS machine (GNOME desktop) today, plus a standalone Home Manager profile
for WSL; structured so a third machine/context is cheap to add later.

## Structure

```
flake.nix, flake.lock        entry point: wires everything below together
lib/
  mksystem.nix                hostname -> nixosConfigurations.<hostname>
  mkhome.nix                  { username } -> homeConfigurations.<username> (standalone HM, e.g. WSL)
hosts/
  nixos/                       the one NixOS system config: laptop, booted into GNOME
    default.nix                  imports ./{common,hardware-configuration}.nix
                                  plus modules/nixos/desktop/{gdm,gnome}.nix
    common.nix                   bootloader, LUKS, network, user, timezone, stateVersion
    hardware-configuration.nix   generated by nixos-generate-config, don't hand-edit
home/<name>/                  one Home Manager config per person/context
  default.nix                  DE-agnostic base (dev tools, shared terminal, browsers, ...)
  gnome.nix                    thin: default.nix + the GNOME home-manager desktop module
modules/
  nixos/                      reusable NixOS-level pieces
    common.nix                 applies to every host
    desktop/                   gdm.nix (GNOME's native login manager), gnome.nix
  home-manager/                reusable Home Manager pieces
    common.nix                  applies to every home (fonts, etc.)
    desktop/                    GUI apps (alacritty.nix, ghostty.nix, gnome.nix dconf/theme tweaks)
    development/<tool>/         one dir per dev tool
      default.nix                 the actual config
      files/                      vendored raw config files (lua, kdl, ...)
```

## Structure Motivation

- **`hosts/` and `home/` are thin.** Each file there is just "which modules
  does this specific machine/person want," plus the handful of settings that
  genuinely can't be shared (LUKS UUIDs, username, git identity). Everything
  reusable lives in `modules/` so a second host or home mostly just picks
  from the same shelf instead of copy-pasting.
- **`modules/nixos` vs `modules/home-manager` mirrors the real split**
  between what NixOS manages system-wide (users, boot, desktop manager) and
  what Home Manager manages per-user (dotfiles, shell, dev tools) — see
  [NixOS vs Home Manager](https://nix-community.github.io/home-manager/index.html#ch-nixos)
  if that boundary is unclear.
- **`lib/mksystem.nix` / `lib/mkhome.nix`** exist so `flake.nix` stays a thin
  list of `mkSystem "hostname"` / `mkHome { username = "..."; }` calls as
  more hosts/homes get added, instead of the boilerplate growing inline.
- **`development/<tool>/files/`** holds real vendored files (e.g. the neovim
  lua config, the gnome-shell theme CSS) rather than everything being
  generated from Nix strings — easier to read/edit, and lets you drop in
  upstream files (like a theme pulled from a project's own repo) with zero
  translation.

## How things are tackled

- **New files must be `git add`ed before Nix can see them.** Flakes only
  look at git-tracked content; a brand-new file that isn't staged yet will
  make `nix build`/`nixos-rebuild` fail with a "not tracked by Git" error
  that has nothing to do with the file's content. Stage first, then build.
- **Validate before switching:**
  ```
  nix flake check --no-build
  nix build .#nixosConfigurations.nixos.config.system.build.toplevel
  ```
- **Apply on NixOS:** `sudo nixos-rebuild switch --flake .#nixos`
- **Apply standalone Home Manager (e.g. WSL, or fast-iterating on the GNOME
  desktop profile without a full system rebuild):**
  `home-manager switch --flake .#<username>` (`wsl` or `gnome`)
- **Shared defaults use `lib.mkDefault`** (see `zellij/default.nix`'s
  `default_shell`) so a module usable by multiple homes has a sensible
  default that any one home can override with a plain assignment, no
  `lib.mkForce` needed.

## Setting up the `wsl` home on a new Linux machine

Bootstraps this repo's `homeConfigurations.wsl` (`home/wsl/`) on a machine
that's never touched Nix before — e.g. a fresh WSL install. Nothing here
needs root except installing Nix itself. This profile has no
home-manager-managed secrets or git config — see "Structure Motivation"
above for why.

1. **Install Nix** via the
   [Determinate installer](https://github.com/DeterminateSystems/nix-installer)
   (flakes enabled by default, no `nix.conf` editing needed):
   ```
   curl --proto '=https' --tlsv1.2 -sSf -L https://install.determinate.systems/nix | sh -s -- install
   ```
   Open a new shell, then confirm with `nix --version`.

2. **Clone over HTTPS** (public repo, no GitHub credentials needed):
   ```
   git clone https://github.com/arbywrk/arby-nix.git ~/.config/nixos
   cd ~/.config/nixos
   ```
   No `git` installed? `nix shell nixpkgs#git` gets a temporary one.

3. **First activation:**
   ```
   nix run home-manager/master -- switch --flake .#wsl
   ```
   ([Home Manager: standalone installation](https://nix-community.github.io/home-manager/index.html#sec-install-standalone)).
   After this, `home-manager switch --flake .#wsl` works directly for future
   changes (validate first with `nix flake check --no-build`).

4. **Set up git identity manually.** `home/wsl/default.nix` deliberately
   doesn't touch `~/.gitconfig` — this profile's git config (including any
   work-specific email/signing setup) is managed outside this repo. Set it
   up the way your work environment expects (e.g. `git config --global
   user.name/user.email`, or whatever your org's own tooling provides).

5. **Confirm it worked:** `zellij` opens themed with the relocated keybinds;
   `nvim` icons render — on WSL specifically, also install
   [JetBrainsMono Nerd Font](https://www.nerdfonts.com/font-downloads) on the
   **Windows** side, since `home.packages` only reaches the Linux-side store.

## Troubleshooting

- **`error: The option '<x>' does not exist`, or "conflicting definition values"
  naming two different values for the same option** — almost always a typo
  (`program.foo` instead of `programs.foo`) or two modules independently setting the
  same option (e.g. `programs.lsd.enable = true` already sets its own `ls`/`ll`/...
  zsh aliases; adding `home.shellAliases.ls` on top of that collides). Read the
  file/line the error names — the module system won't silently pick one for you.
- **`... is not tracked by Git`** — flakes only evaluate git-tracked content;
  `git add` the new file before `nix build`/`switch` can see it (see "How things are
  tackled" above).
- **nvim/zellij glyphs render as boxes or `?`** — terminal-emulator-side font issue,
  not a Nix one; see the Nerd Font note in step 5 of the `wsl` home setup above.
- **`nix run`/`switch` fails with a TLS/certificate error on a corporate machine
  (e.g. WSL)** — the corporate root CA is trusted by Windows but not WSL's separate
  Linux trust store. Export the root (and intermediate, if present) cert from
  Windows' `certmgr.msc`, install into Ubuntu:
  ```
  sudo cp *.crt /usr/local/share/ca-certificates/
  sudo update-ca-certificates
  ```
  then point Nix at the merged bundle by adding to `/etc/nix/nix.conf`:
  ```
  ssl-cert-file = /etc/ssl/certs/ca-certificates.crt
  ```
  and restarting the daemon (`sudo systemctl restart nix-daemon`).
- **GNOME Shell theme (`modules/home-manager/desktop/files/gnome-shell/`)
  changes not showing up** — GNOME Shell caches the parsed stylesheet in
  memory and doesn't watch the file; after `home-manager switch`, force a
  reload with:
  ```
  gnome-extensions disable user-theme@gnome-shell-extensions.gcampax.github.com
  gnome-extensions enable  user-theme@gnome-shell-extensions.gcampax.github.com
  ```
  (Wayland has no shell-restart shortcut short of logging out.)
